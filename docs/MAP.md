# MAP

burrow is an ssh client in wolf. This map says what it is made of, what it
speaks and refuses, and what is measured where. Sources are in
[SOURCES](SOURCES.md).

## Milestones

| | milestone | state |
|---|---|---|
| **B0** | the map: scaffold, pinned toolchain and oracle, tiered CI, this census, the differential harness, the prediction | done |
| **B1** | the transport: version exchange, binary packet protocol, `curve25519-sha256`, `ssh-ed25519` host keys against known_hosts, `chacha20-poly1305@openssh.com`, strict kex, ext-info, rekeying, disconnect | done |
| **B2** | auth and keys: `publickey` with `ssh-ed25519` (RFC 4252, 8709), the OpenSSH private key format (`PROTOCOL.key`), `burrow-keygen -t ed25519`, known_hosts appending and hashed `\|1\|` entries | not yet |
| **B3** | channels and the CLI: a session channel, `exec` and `env`, byte-clean stdin/stdout/stderr, windows, EOF and close, exit status, the `ssh` options den uses | not yet |
| **B4** | den over burrow: clone, fetch and push through burrow, then on PAX | not yet |

Until B2, `burrow` stops after SERVICE_ACCEPT with "not yet implemented: user
authentication" and exit status 2.

## What burrow speaks

| list | burrow offers, in order |
|---|---|
| kex | `curve25519-sha256`, `curve25519-sha256@libssh.org`, `ext-info-c`, `kex-strict-c-v00@openssh.com` |
| host key | `ssh-ed25519` |
| cipher, both directions | `chacha20-poly1305@openssh.com` |
| MAC, both directions | `hmac-sha2-256` (never used: the cipher is an AEAD, which ignores the MAC lists) |
| compression, both directions | `none` |
| languages | none |
| first_kex_packet_follows | false; a wrong guess by the server makes burrow ignore its next packet (RFC 4253 §7.1) |

## What burrow refuses, by name

Every refusal prints `burrow: <name>: <detail>`, sends SSH_MSG_DISCONNECT with
the reason code below when the connection can still carry one, and exits 255.

| name | when | reason |
|---|---|---|
| `connect_refused` | nothing listens at the address | (no connection) |
| `banner_too_long`, `banner_too_many` | a line before the server's version over 8192 bytes, or more than 1024 of them | 8 |
| `version_too_long` | the server's identification over 255 bytes, CR LF included | 8 |
| `version_malformed` | not `SSH-protoversion-softwareversion[ SP comments]`, or a NUL | 8 |
| `version_unsupported` | a protoversion other than 2.0 or 1.99 | 8 |
| `packet_too_short`, `packet_too_long` | `packet_length` under 12 or over 262144 | 2 |
| `padding_short`, `padding_overrun` | under 4 bytes of padding, or padding that overruns the packet | 2 |
| `unaligned` | a frame off its multiple of 8 | 2 |
| `mac_mismatch` | a sealed packet whose Poly1305 tag does not verify | 5 |
| `malformed`, `message_unexpected` | a message that does not parse, or arrives where it may not | 2 |
| `no_common_kex`, `no_common_hostkey`, `no_common_cipher`, `no_common_compression` | negotiation finds no common algorithm; RSA, ECDSA, the finite-field and post-quantum hybrid methods, AES and every other name are refused this way | 3 |
| `strict_kex_missing` | the server does not offer `kex-strict-s-v00@openssh.com` (waived by `--no-strict-kex`) | 3 |
| `strict_kex_violation` | under strict kex, any message the first exchange does not need, including one before the server's KEXINIT | 2 |
| `kex_failed` | an all-zero X25519 output, a Q_S that is not 32 bytes, or a re-exchange the server answers with UNIMPLEMENTED | 3 |
| `host_key_unsupported` | a host key or signature that is not `ssh-ed25519` | 3 |
| `host_key_bad_signature` | the server's signature on H does not verify | 3 |
| `host_key_unknown` | no known_hosts entry names this host with an `ssh-ed25519` key | 9 |
| `host_key_changed` | an `ssh-ed25519` entry for this host holds another key, a `@revoked` line names this key, or the key changes in a re-exchange | 9 |
| `known_hosts_unreadable` | a known_hosts file exists and cannot be read | 9 |
| `service_refused`, `auth_refused` | the server does not accept the service, or the rows' `none` login | 7, 14 |
| `entropy_unavailable` | `/dev/urandom` cannot be read | 11 |
| `sequence_wrapped` | a sealed direction's sequence number wrapped before a rekey | 2 |
| `disconnected`, `closed`, `timeout`, `io` | the server's own DISCONNECT (its reason is printed), or the socket's end, deadline or failure | (none sent) |

## The census: what the RFCs and notes ask, and what burrow does

| source | asks | burrow |
|---|---|---|
| RFC 4253 §4.2 | version line ≤ 255 bytes with CR LF; banner lines before it; no NUL | done; a bare LF is accepted, as §4.2 suggests |
| RFC 4253 §4.2 | no `-` in softwareversion | accepted there anyway: deployed servers send one |
| RFC 4253 §6 | padding ≥ 4, frames a multiple of 8, `packet_length` included | plaintext frames, as written; sealed frames align `packet_length` alone, the measured rule (below) |
| RFC 4253 §6.1 | 35000-byte packets at least | up to `packet_length` 262144 received; burrow sends small ones |
| RFC 4253 §7.1 | negotiation, first_kex_packet_follows, no non-kex messages during kex | done |
| RFC 4253 §7.2, §8 | the exchange hash and key derivation | done, held to `tools/vectorgen.py`'s independent vectors |
| RFC 4253 §9, RFC 4344 §3 | rekey at 1 GiB or an hour; before 2^32 packets (2^31 on receipt) | 1 GiB either direction, 2^31 packets either direction, one hour; the server's KEXINIT any time |
| RFC 4253 §11 | DISCONNECT, IGNORE, DEBUG (shown with `-v`), UNIMPLEMENTED | done |
| RFC 8308 | `ext-info-c`; EXT_INFO after NEWKEYS; unknown extensions ignored | done; `server-sig-algs` kept for B2 |
| RFC 8731 | X25519, all-zero abort, 32-byte public values, K as mpint | done |
| RFC 8709 | `ssh-ed25519` key and signature blobs | done; verification is wolf-std's cofactorless Ed25519 |
| RFC 9142 | `curve25519-sha256` SHOULD; `ext-info` SHOULD | done |
| RFC 9142 | `diffie-hellman-group14-sha256` MUST | not implemented: refused by name (`no_common_kex`); every target server offers curve25519 |
| `PROTOCOL` §1.10 | strict kex | done, and required by default |
| `PROTOCOL` §1.9 | PING/PONG | answered; the traffic rows use it |
| `PROTOCOL.chacha20poly1305` | the AEAD, the tag checked before decryption, compared in constant time | done |
| `PROTOCOL.certkeys` | certificate host keys | refused by name (`no_common_hostkey`; burrow does not offer them) |

## Constant time

The one comparison of secret-dependent data burrow makes itself is the
Poly1305 tag check in `chachapoly.open`, through `wire.ct_eq`: every byte
pair is folded into one accumulator before anything is tested, and nothing
is decrypted before it passes. Key derivation, the exchange hash, X25519,
ChaCha20 and Poly1305 are wolf-std's and carry its `ct:` lines. Host keys,
signatures and the exchange hash the server signs are public.

## The oracle, measured

OpenSSH 10.0p2 built from its signed tarball (`burrow-oracle.toml`). With
ed25519, ecdsa and rsa host keys, its `sshd` offers (`tools/oracle-probe`):

| list | the pinned sshd |
|---|---|
| kex | `mlkem768x25519-sha256, sntrup761x25519-sha512, sntrup761x25519-sha512@openssh.com, curve25519-sha256, curve25519-sha256@libssh.org, ecdh-sha2-nistp256, ecdh-sha2-nistp384, ecdh-sha2-nistp521, ext-info-s, kex-strict-s-v00@openssh.com` |
| host key | `ssh-ed25519, ecdsa-sha2-nistp256, rsa-sha2-512, rsa-sha2-256` |
| cipher | `chacha20-poly1305@openssh.com, aes128-gcm@openssh.com, aes256-gcm@openssh.com, aes128-ctr, aes192-ctr, aes256-ctr` |
| MAC | the five `-etm` variants, then `umac-64@openssh.com, umac-128@openssh.com, hmac-sha2-256, hmac-sha2-512, hmac-sha1` |
| compression | `none, zlib@openssh.com` |
| EXT_INFO | `server-sig-algs`, `publickey-hostbound@openssh.com`, `ping@openssh.com` |

Three black-box findings shape B1:

- **Sealed frames align `packet_length`, not the whole frame.** Under
  `chacha20-poly1305@openssh.com` the pinned `sshd`'s first sealed packet has
  `packet_length` a multiple of 8, and RFC 4253 §6's whole-frame rule refused
  it (`unaligned`). burrow sends and expects the measured rule; plaintext
  frames keep §6's.
- **No re-exchange before user authentication.** The pinned `sshd` logs a
  client KEXINIT after SERVICE_ACCEPT as a protocol error and answers it with
  UNIMPLEMENTED; it does not start one itself there either. burrow refuses by
  name (`kex_failed`) rather than wait. The rekey rows therefore log in first
  with RFC 4252's `none` method, as an empty-password account the row's
  `sshd` admits.
- **OpenSSH's client offers `zlib@openssh.com` even with `Compression=no`.**
  Its KEXINIT is otherwise byte-identical to burrow's after the cookie, when
  it is given burrow's lists.

## Gaps, named

- Hashed known_hosts names (`|1|`) need HMAC-SHA1; wolf-std has no SHA-1.
  They are skipped until B2 brings one (den vendors one with provenance).
- wolf-std has no entropy source; burrow reads `/dev/urandom` (PAX needs one).
- The pinned wolf-std's Ed25519 `verify` accepts small-order keys
  (cofactorless, as RFC 8032 allows); `verify_strict` lands in a later std.
